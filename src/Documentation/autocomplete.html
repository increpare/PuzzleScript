Advanced Autocomplete

PuzzleScript has fancy autocomplete for objects and rules.

For instance, if you create an objected called Enemy_up, if as your next object you start typing C you will see in your autocomplete a suggestion to generate the rest (_down, _left, _right), which will also rotate the sprites with them.

There's been autocomplete added for many suffix variants:

This is not the end, though! If you type one rule that starts with a direction, if you add a new rule to the next line that starts with a direction, you will be prompted with a transformed version of that rule.

How do we decide how to transform the rule? It depends on the two directions. If they are 90 degrees apart, it's a rotation, otherwise we mirror the rule. If we have an up rule, a following down rule will be autocompleted as a vertical mirror: 

up [ > Player | up Crate_up ] -> [ > Player | right Crate_right ] 
down [ > Player | down Crate_down ] -> [ > Player | right Crate_right ]

But if we autocomplete in series up, right, down, the down rule will be effectively a 180 degree rotation of the original up rule: 

up [ > Player | up Crate_up ] -> [ > Player | right Crate_right ] 
right [ > Player | right Crate_right ] -> [ > Player | down Crate_down ]
down [ > Player | down Crate_down ] -> [ > Player | left Crate_left ]

This will do its best to transform any objects with suffixes mentioned in the above table, along with any movement directions mentioned.

Repeat a rule for another family

Autocomplete can also repeat earlier rules for related names. For example, after writing: 

[ RedKey | RedDoor ] -> [ | ]

Start a new rule line with Blu. If BlueKey and BlueDoor are defined, the menu offers Repeat for Blue. It shows the exact changes (RedKey → BlueKey; RedDoor → BlueDoor) and previews the complete rule: 

[ BlueKey | BlueDoor ] -> [ | ]

Select the suggestion and press Tab or Enter to insert it. The names must have a consistent change between CamelCase words, underscore-separated parts, or numbers. This also works for OpenDoor / ClosedDoor, WoodBox / MetalBox, and key_red / key_blue. Every resulting name must already exist. Commands, movement directions, comments, and message text are preserved.

Numbered transitions keep their step: typing 2 can repeat [ Stage1 ] -> [ Stage2 ] as [ Stage2 ] -> [ Stage3 ], provided all three stages exist. Other numbered parts of a name remain unchanged. Recent examples take priority; autocomplete looks back through 500 lines of parsed rules, skips rules already present, and shows at most twelve repeats. When a rule starts with a direction, the existing rotate/mirror suggestion handles its _up/_down/_left/_right names together with the rule direction.

Suggestions that fit the rule

Suggestions use the current game definitions. Late rules omit forbidden movement modifiers; win conditions offer on after their first object; and a cell's object suggestions omit combinations known to conflict on a collision layer. An incomplete or uncertain definition is not enough to rule out a suggestion.

A property on the right means the same object matched on the left. Autocomplete explains whether it is bound by the corresponding cell or by one unique occurrence in the left-hand pattern. If the left side is clear and supplies neither binding, that property is omitted. Property aliases have their own names for this purpose: use the same property name on both sides. no Property excludes all its members and random Property chooses a member on the right, so these do not need that binding.
